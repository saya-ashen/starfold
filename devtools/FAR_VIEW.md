# Far-view diagnostics

The client-only devtools extension is off by default. For a Gradle development client, add `-PdevFarDiagnostics` to load it. Existing `/sfprofile start|stop` remains independent.

Commands registered on the NeoForge client dispatcher:

- `/sffar` or `/sffar status`: report state and retained counts without writing files.
- `/sffar watch`: watch the observer's current face tile, radius 0.
- `/sffar here [radius]` or `/sffar watch here [radius]`: same selection with optional radius.
- `/sffar watch <face> <x> <z> [radius]`: watch a tile of the current Ground planet. Face is 0..5; x/z are chart-face block coordinates 0..2047 normalized down to a 16-block origin. Radius 0..2 is measured in tiles, clipped at chart boundaries, at most 25 tiles. These are not storage/world chunk coordinates. Requires current observer metadata.
- `/sffar snapshot`: capture the center tile's loaded raw world evidence and write the retained history plus current core evidence; continue watching if the window is active.
- `/sffar stop`: freeze and release the core watch, then export. A failed export retains evidence for retry.

Reports are UTF-8 JSON plus `.json.summary.txt` under `<gameDirectory>/diagnostics/far-view/`, with unique generated names. Only explicit `snapshot` and `stop` write files. A capture freezes after 2400 client ticks or 120 seconds checked on ticks, or disconnect. Frozen data remains exportable; starting another watch replaces it. A running watch must be stopped before replacement. Retention: 128 distinct periodic region states, 2048 deduplicated events, one latest core snapshot. Core has independent event, geometry and CPU-record caps; all loss counters remain in JSON. Tick capture performs no raw-world sampling or file IO.

Raw export covers only the center 16x16 tile, even with radius >0. It maps columns into the current client chart, reads only `getChunkNow`, and samples WORLD_SURFACE occupied Y minus 8 through plus 2, clipped to world height. No column scan to bedrock, chunk request, mesh recomputation, GPU read, or fluid world-flow query is made. Explicit coordinates, sample bounds, fluid type/properties/source/flowing/height, loaded neighbor evidence, light meaning, and unknown/unloaded/truncation counts are exported. The bounded block-read budget includes supplemental neighbor reads. Raw time differs from historical region/geometry times.

The analyzer observes contiguous native-window true-to-false transitions within a single epoch. A gap candidate requires the renderer and selection active, native window false, all recorded resident/previous/chart/parent/staged meshes absent, and this condition persisting strictly more than two seconds after an observed exit. A sample gap over one second, missing tile, or epoch reset breaks continuity. This is CPU state evidence; it does not establish actual native ownership, exterior fallback coverage, shader acceptance, or GPU pixels. Request/draw restoration evidence must occur after the observed exit and before the applicable state sample, for the same tile, planet and epoch.

`INCOMPLETE` is explicit when native exit, periodic region state, CPU geometry, or complete loaded primary raw sampling is absent, or retained histories were truncated. `OBSERVED` means the listed bounded evidence was observed, never that rendering passed a visual test. Findings are separate from evidence completeness. Null region/mesh evidence means unavailable; false booleans in a present region are observed false. Mesh vertex/quad evidence retains core stages, versions and raw coordinates without claiming GPU visibility.

When a watched center tile participates in a far draw, `core.records` may also contain `stage: "DRAW_GPU_STATE"`. These records run on the render thread after shader application and custom uniform/sampler assignment, before drawing. They distinguish `AFTER_ENTITIES` opaque and `AFTER_PARTICLES` translucent passes, layer, chart/parent/stitch/resident source, mesh path, shader identity and program, source face and native/cover/derived/stitch flags. Effective scalar uniform values come from the actually bound GL program; inactive uniforms are explicit. Coverage includes the effective sampler unit, actual texture binding, and sampler object, with the previous active texture unit restored. There is no framebuffer or texture readback. `cpu.atlas` reports the addressed texel and the retained CPU arguments of the last coverage upload, explicitly distinct from GPU contents. Current draw-time ownership/native-window inputs are independent of the last completed `AFTER_PARTICLES` region state.

Draw-state capture is one-shot per watch epoch, source, chunk layer and stage (at most 60 records), only for the watched source face and center patch/resident range. These observations are protected from ordinary CPU-record eviction until watch/reset within the existing 128-record total cap; excess draw records and CPU evictions increment the existing loss counter. Patch or face batch inclusion does not identify the visible primitive. After a slot is consumed it performs no further GL queries; stopping the watch disables capture. Begin a fresh watch to rearm. Missing draw records mean unavailable evidence. The existing JSON records channel and `far_snapshot` operation carry these fields without a protocol change. On a later launch with the rebuilt core and devtools jars, start a watch at face 5 chart `(992,976)` to address the north wall texel `(63,712)`; `(992,992)` addresses the south texel `(63,713)`. No launch, deployment or capture is performed by the offline build.

Core requirements: public `dev.starfold.api.FarViewDiagnostics.watch`, `snapshot` (`region()`), `active`, and `stop`; immutable Gson-serializable snapshot records, monotonic event sequences, epoch/planet provenance, bounded geometry and CPU records. Core has no dependency on devtools. The raw adapter additionally uses the existing public `GroundClient` chart mapping, readiness, current planet, face and eye accessors.

Offline fixtures in `FarAnalyzerTest` cover unavailable versus false, starting outside native range, grace boundaries, epoch/reset and sample discontinuity, restoration event timing, deduplication, overflow and missing-sequence accounting. `FarRawCaptureTest` covers loaded/unmapped/unloaded columns, surface bounds, fluid neighbors, light availability and hard read caps. `FarReportTest` checks JSON nulls/provenance and exported summary. Validation can use direct Java 21 compilation and a cached JUnit platform launcher without invoking Gradle or launching the game. Integration validation should check client command registration, snapshot/stop file pairs, automatic expiry without file writes, disconnect, and both observer-here and explicit chart tile selection.
