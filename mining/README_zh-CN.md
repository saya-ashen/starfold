# Starfold：基础采矿

阶段一的固定式采矿平台，帮助母星开局从少量手工采矿过渡到持续获取建筑材料与深层矿石。它是独立可选模块，依赖 Starfold 核心；不要求安装 Atlas 才能工作。

## 制作与使用

配方：四块铁锭、两块铜锭、一把铁镐、一个熔炉和一个拉杆。无需红石、钻石、锇或 FE 发电设备。

从原料筹备时，铁镐另需三块铁锭，因此一台平台合计需要 **7 铁锭、2 铜锭、9 圆石和 3 木棍**：8 圆石制作熔炉，1 圆石与 1 木棍制作拉杆，另 2 木棍用于铁镐。工作台、其他工具、冶炼燃料和开机燃料另备。建议保留家用熔炉，另造一座作为机器材料。

1. 在任一星球的固定地面放置平台，圈出下方 **5×5** 井口，防止人和动物跌落。外观为单方块钻机，井口范围与机器占地不同。
2. 右键打开面板，放入熔炉可用燃料；也可以从任意面接入 FE。
3. 点击「探矿」。平台检查正下方 5×5、深 512 格的已加载地层，消耗能量，记录矿种、数量和相对深度。扫描不挖除方块。井底必须仍在世界高度范围内；平台放得太低时会直接拒绝开始，不消耗扫描能量。
4. 探矿完成后点击「开始」。平台从第一层开始逐层开挖，石料也会进入产物槽，不会跳过覆盖层直接提取深处矿石。
5. 定期取走两行产物。漏斗等物品管道可提取产物；燃料可自动输入。缺能或产物装满时保留进度，恢复条件后继续。遇到流体、不可破坏方块、方块实体或保护限制时停止，先处理现场。
6. 可暂停或保存退出；燃料、能量、矿物汇总和扫描/挖掘位置保存到世界。重置需先暂停，保留库存和能量，但清除本次扫描与挖掘计划。

## 暂定数值

| 项目 | 首版数值 |
| --- | --- |
| 工作范围 | 5×5，向下 512 格；触及不可开采方块会提前停止 |
| 内部储能 | 20,000 FE |
| 探矿 | 每刻最多检查 64 格，每格 2 FE |
| 开采 | 每刻最多处理一个位置，20 TPS 下每秒最多 20 块，实际破坏每块 80 FE |
| 燃料 | 每个熔炉燃烧刻仍折算 10 FE。作业时按需加快转换，固体燃料可维持满速开采 |
| 产物槽 | 18 格 |

FE 和燃料共用内部储能；有外部供能且储能充足时，不会白白烧掉燃料。煤或木炭的名义总供能为 16,000 FE。完整最大范围扫描需要 25,600 FE；单次扫描期间需持续供能。按预算，2 份煤或木炭可支付扫描，剩余 6,400 FE 可支付 80 次实际方块破坏；实际还受阻挡、输出空间等条件影响。若希望扫描后至少挖 100 块，应准备 3 份，而不是把 2 份扫描燃料当作整次采矿总成本。实际开采速度、总燃料和产物搬运量仍需整包从零生存游玩调优。

## 探矿与地图

安装 Atlas 后，已完成探矿的地点显示在星球图上，包含已扫描范围、矿物数量、深度和记录时间。结果归平台放置者所有，并通过普通私人航点导航。记录是历史快照，不实时显示已挖走的矿物，也不代表未扫描区域没有矿。

平台处理行星固定地面的竖井，井口须完整落在同一星球的真实区块内。拥有者离线或作业区区块卸载时暂停；不提供船载采矿、离线产出、跨星球调度、远程强制加载或整颗行星资源化。游戏中的开采会真实改变方块；地形保护、液体及安全围栏仍由玩家处理。

## 阶段二：紧凑抽油机

方块、物品、方块实体及菜单 ID 均为 `starfold_mining:oil_extractor`。固体矿机保持独立；抽油机只在安装 CDG 时启用。没有 CDG 时面板明确显示「未安装CDG · 抽油禁用」，不加载 CDG 类，固体采矿不受影响。原油是流体和逻辑区块油藏，**不是地下原油方块**。

配方（3×3）：

```text
铁锭   铁栏杆   铁锭
铜锭   空桶     铜锭
铁锭   熔炉     铁锭
```

材料均在母星早期可达，无 Create 机械、原油、塑料、锇或其他星球产物的自举依赖。配方中的栏杆代表折叠钻杆组件，井路不另收数百根实体管道。4 铁锭、2 铜锭、1 铁栏杆、1 空桶、1 熔炉是直接材料；单独新做栏杆需 6 铁锭（产出16根）、空桶需3铁锭，因此从零且无库存时需准备13铁锭、2铜锭和8圆石，剩余15根栏杆可留用；冶炼和开机燃料另备。

1. 放在母星真实拥有的 canonical 区块内固定地面。面缝的展示别名、其他星球、Sable 船体存储区均拒绝工作；设备锚点记录原维度与位置，搬迁后不能继续使用原井。只有放置者能控制作业，且放置者必须在线。设备不发区块票、不强制加载。
2. 放入熔炉燃料，或任意侧接 FE。点「勘探」只付费查询**本机所在一个真实区块**的 CDG 油藏；不扫描整颗星球。完成后显示最近一次储量读数。读数是快照，其他 CDG 抽油机可能继续消耗它。
3. 有油后点「建井」。本版是**不破坏地层的虚拟井**，只沿正下方单列逐层验证，不掉矿、不移走方块。正常石/土/沙/矿石/空气可通过；流体、方块实体、玩家建筑及非地层白名单、不可破坏或 immutable 方块停止。只在真正遇到 `starfold:core_shell` 或 `minecraft:bedrock` 时成井，最大深度1024，并受实际世界高度限制。该上限独立于固体平台的512格扫描，覆盖2048尺寸母星约667层的地表到核心井路。
4. 每层含空气都以放置者 UUID 的生存假玩家执行 `mayInteract`、出生点保护及 NeoForge `CommonHooks.fireBlockBreak` 保护事件；普通地层另执行 `canEntityDestroy`。井底只是非破坏传感器，因此不要求地核/基岩可被破坏，但照样检查领地与保护事件。建井每次推进和抽油每批前复核既有井路，事件修改过的地层不会被旧检查放行。若补燃料会调用其他模组的燃烧时间或容器回调，供能后还以原状态快照检查井道及下一目标；此复核不再次触发保护回调。保护模组若拒绝假玩家或拒绝对基岩的 break 检查，会明确停机；不会绕过取消事件。
5. 成井后点「抽油」。油先进入16桶内部罐。空桶右键取油；任意面可接流体管道抽出。外部流体能力严格只出不进（包含空方向），能量严格只进不出。没有主动向不可信管道推油的操作，由标准 NeoForge drain 能力对接管道。
6. 燃料槽可用漏斗/管道输入；余物槽可被抽取（例如熔岩桶留下空桶）。容器余物放不下时不会吞燃料。暂停、离线、缺CDG及满罐不烧燃料。满罐不扣 FE、不扣油藏；油罐只剩部分空间时按实际接收的 mB 结算。
7. 正常保存/退出后保留 owner、原位锚点、勘探进度、井深、工作时钟、FE、剩余燃烧刻、库存、罐内原油、开关与状态。恢复后重新检查在线所有者、位置与井路，并重新读取 CDG 实时储量，不能凭保存的读数再发一份油。拆除掉落普通设备及两格物品库存，**丢弃内部油/FE/井进度**；拆前先用桶或管道排空。

### 首版参数与预算

| 项目 | 首版值 |
| --- | --- |
| FE容量 / 油罐 | 20,000 FE / 16,000 mB |
| 勘探 | 100工作刻，每刻10 FE，共1,000 FE |
| 虚拟建井 | 最大1024层，每层80 FE，足够供能时每10工作刻推进一层 |
| 抽油 | 每20工作刻最多100 mB，每实际接收1 mB消耗2 FE |
| 燃料发电 | 需要能量时按每工作刻10 FE预算；建井按10刻、抽油按20刻周期，在验证井路后结算该周期的燃烧预算，余下燃烧时间保存 |
| 接口 | 各面收FE、排原油；燃料输入槽0、容器余物输出槽1 |

例如井底距设备200格时，建井花16,000 FE，加勘探共17,000 FE；抽满16桶还需32,000 FE，总49,000 FE。煤/木炭每份名义16,000 FE，4份可覆盖这份预算。有FE持续供能且路径通畅时该示例建井约100秒，抽满约160秒；燃料也按10刻周期提供最多100 FE，足以支付每层80 FE；余物阻塞、缺料或路径检查等待会延长实际时间。这些是首版可测参数，尚未做整包生存平衡。

### 固定 CDG 1.3.15 核验

本地核验对象：`build/pi/jars/createdieselgenerators-1.21.1-1.3.15.jar`，SHA-256 `56ef1d574278fc311f1ffa223dbd613077b899354a18d01ae8dca2578a4e2990`。用 `javap -p -c` 检查了 `com.jesz.createdieselgenerators.world.OilChunksSavedData` 和 `content.pumpjack.PumpjackHoleBlockEntity.pumpjackRotation`，没有凭类名猜 API。

窄适配器 `CdgOilReservoir` 仅反射以下真实方法：

- `OilChunksSavedData.load(ServerLevel)`：使用该维度 DataStorage 中的 `cdg_oil_chunks` SavedData。
- `getChunkOilAmount(ChunkPos): int`：读当前油量，单位mB。缺条目会按CDG配置/种子/生物群系计算；大于无限阈值时返回 `Integer.MAX_VALUE`。
- `setChunkAmount(ChunkPos, int): void`：更新共享 map，并调用 `setDirty()`。有限油扣除实际接收量；抽完明确写0，绝不 `removeChunk`（删除条目会重新生成初始储量）。无限油遵循 CDG 抽油机行为，不扣减。

SavedData 原生保存的是 `OilChunks` 列表（`x`、`z`、`Amountmb`），旧 `Amount` 加载时换算为mB。本模块不造第二份储量、不改CDG生成公式或配置。调用前要求真实区块已加载；canonical真实坐标才会进入 CDG。每秒最多一次抽油作业尝试；先完成井路保护回调，再读取实时油藏。同一同步事务的预检与结算共用该读数；若供能可能启用新燃料并调用其他模组的燃烧时间／容器回调，则在这些回调后重新取一次余额。下一事务创建新适配器重新读取共享油藏。避免停电重试或无限油把CDG未缓存的12,800次生物群系采样放大到每刻调用，同时不覆盖其他回调刚刚扣除的储量。

适配缺方法、异常或链接错误会记服务端日志并明确停用，不能静默给油。罐内插入与 FE/储量结算期间屏蔽外部 drain、延迟dirty；CDG写失败或插入异常回滚罐。设备没有比较器输出，dirty只标记已加载的自身区块，不走 vanilla `setChanged` 的邻居遍历（它可能在区块边界读取两格外的未加载区块）。正常保存会同时让油罐与CDG SavedData落盘；Minecraft不同存档文件间不提供崩溃原子事务，因此不承诺进程在磁盘写到一半时的断电恢复原子性。

### 验证与当前边界

最新 `:mining:test :probes:compileJava` 通过；采矿模块共11项测试通过，其中抽油策略9项、固体扫描体积2项。人工5000 mB共用油藏的隔离实机已通过守恒与两次新JVM完整NBT恢复：CDG 2000 + 机内1963 + 已审计排出1037 = 5000 mB；覆盖满罐、最后1 mB、模拟／实际排出、桶取油、保护取消、井路受阻与暂停。新增保护与燃料回调竞争回归也已通过：只按回调后的1mB余额转移，准确消费一份煤，燃料回调注水则受阻停机而不扣油；完整记录见[阶段2记录](../docs/stage2-runtime-2026-11-10.md)。这些夹具不代表自然找油或连续生存已完成。纯策略 `OilCycleTest` 覆盖满罐、部分容量、FE预算、simulate/实际接收差异、两台机器共用有限油、写0枯竭、无限油、CDG写失败及插入异常回滚、进度保存恢复与损坏值边界；已有 `MiningVolumeTest` 保留。资源以JSON/PNG静态校验，packagingContract新增抽油机资源契约。

剩余检查包括：无CDG时的实际启动提示、自然深井与连续生存、抽油机到外罐的实际管道、余物满槽、新领地、作业中离线与边界卸载、Sable组装、母星接缝真实区块对油。有CDG的实际加载、守恒重启、满罐／最后1mB、桶、六面流体能力与保护／注水／放BE停机已在隔离夹具中验证。井路全量保护检查的性能及CDG无限油配置需游戏实测。Atlas油记录与星球图联动本版未接入；完整抽油面板独立可用。
