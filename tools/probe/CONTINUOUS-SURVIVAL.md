# Copper Swift 阶段 2 → 4 连续验收设计

一次启动运行器，从含天然原油分馏成品的 Hearth 生存存档出发，在 Fleck 采矿、装货、离船保存，从同一存档重启并找回原船，最后在 Hearth 卸货并制成两个 Mekanism 基础控制电路。两段客户端会话共用一个隔离存档、一个显示和一段连续录像，中间只有一次计划内的客户端与服务端重启。

## 起点与夹具

- 固定当前源码、整合包依赖和已验收的天然分馏存档。正式运行前只读核对种子、玩家、两个成品罐各有 1,000 mB、玩家没有原锇、锇锭或基础控制电路，并记录实际存档来源。运行器只把起始存档复制一次。起点在天然原油分馏完成之后，过往分馏回执随报告引用。
- 沿用铜翼、尖船首的小船夹具和精密机构补给。Fleck 采矿夹具部署固定采矿平台、提供煤，并通过物品能力清理非锇输出和取出 8 份原锇。矿石由平台从自然地层实际挖出。Hearth 加工夹具提供靠近下船点的封闭工位、熔炉、煤、灌注机、红石和电力。通过舵正常组装，从服务端取得本次新船 UUID，后续以该 UUID 关联舵、Atlas、货桶和两个燃料罐。旧验收 UUID 仅用于比对历史证据。
- 玩家一直处于生存模式。飞行、离舵、步行、登船、货桶装卸走实际客户端输入。只读测量、存档控制和上述夹具由服务端提供。

## 第一次会话：装船至 Fleck 离船保存

| 检查点 | 操作与通过条件 |
| --- | --- |
| 装船与离开 Hearth | 转移已存在的柴油和汽油各 1,000 mB，记录两边罐量和守恒回执。正常组装并接管，普通升力起飞。记录同船进入太空参考系、舵权、罐量和实际燃料消耗。参考 `dock-resume.txt`、`ascent-unboosted.txt`。 |
| Fleck 进近 | 检查目标和闭合速度，按当前飞行模式推进。转向只在鼠标飞行状态下下发，`NOTICE` 后沿实测进近状态保持或释放推进，等待正确星球的地表参考系和地形加载。记录模式变化、姿态、燃料和距离。参考 `fleck-final-burn.txt` 及 `fleck-05`。 |
| Fleck 接地与下船 | 预勘天然干地，下降前和接触后都验证整船面边余量大于 104 格，并核对整个落区位于折点地形影响区外。按实际净空释放下降输入，要求持续低速接触、净空不大于 1 格、舷梯服务端展开。通过 R 离舵，沿梯走到自然地面，服务端核对玩家着地、存活且脱离船体追踪。第二次确认离舵或绕过舷梯下船单独记录为降级结果。参考 `fleck-09` 勘测与 `fleck-slope-fixed-01`。 |
| 采矿与入舱 | 验证玩家和货桶起始原锇为零。平台探矿并从天然地层挖出 8 份原锇。经 Baritone 返回舷梯附近，登船后通过货桶界面装货。服务端核对玩家不再持有这 8 份、原船货桶有 8 份，记录船体姿态和燃料。历史手挖与装货证据见 `fleck-osmium-01` 和 `fleck-load-08`。 |
| 离船检查点 | 走到已勘测、可从地面进入回船路线的位置。服务端核对玩家仍在 Fleck、着地、离开原船追踪，货桶仍有 8 份。记录玩家与船坐标、UUID、罐量和货量。结束客户端，再执行 `save-all flush`、`stop`，验证服务端正常退出。 |

## 第二次会话：重启至 Hearth 电路产出

| 检查点 | 操作与通过条件 |
| --- | --- |
| 恢复原船 | 启动新服务端 JVM 并重新登录同一存档。断言起始位置仍在船外。打开 Atlas 选中第一段 UUID，沿实测山脊路线靠近，按启动后的船位选择最后的登船方向。通过步行或跳跃登船，等待原船追踪，再右键接管舵。核对 8 份原锇和重启前罐量。参考 `fleck-recover-03` 的前半路线和 `fleck-recover-04` 的绕坡路线。 |
| 返回 Hearth | 用同船带货起飞，短时推进期间根据 Hearth 相对速度修正瞄准方向，抵消横向漂移。记录闭合速度、飞行模式和罐量，进入 `NOTICE` 后滑行。进入 Hearth 地表参考系后复核原船和 8 份原锇。 |
| 接地与卸货 | 勘测干地，下降前和接触后验证整船面边余量大于 96 格，落区在折点影响区外。驶向已验证的落点时同步下降以节省燃料。舷梯完全展开后释放下降输入，稳定后再次确认舷梯。服务端记录进场前与接触后生命值，单列受伤、舷梯和离舵情况。实际离舵并通过货桶界面取回 8 份，服务端核对入背包与清空货桶，再沿舷梯离开原船。加工夹具在玩家身旁的可用空位放置熔炉和灌注机。以 `hearth-descent-01`、`hearth-unload-02` 为参考。 |
| 首批电路 | 确认玩家已有 8 原锇且没有锇锭和电路。熔炼其中 2 份，核对 2 锭和 6 份剩余原锇。灌注机使用这 2 锭及测试提供的 4 份红石，玩家从产出槽取走 2 个 `mekanism:basic_control_circuit`。服务端须确认电路、剩余原锇和锇锭耗尽，再保存退出。参考 `hearth-circuits-05`。 |

## 运行及判定

`continuous-survival.py` 使用 `continuous-fleck.txt`、`continuous-hearth.txt` 和 `continuous-survival-fixture.js`。可从已有的 `dock-03/instance/regression-stage2-acceptance` 副本开始。该副本含预置码头、未组装的船体、已发放的精密机构和未转移的分馏产物。跑前核对两个成品罐、船上设备及玩家初始库存。脚本从装船和实际接管舵开始录取证据。

```sh
python3 -B tools/probe/continuous-survival.py \
  --source build/acceptance/survival-loop/dock-03/instance/regression-stage2-acceptance \
  --output build/acceptance/continuous-new --port 25632
```

真正启动时加 `--run --baritone-jar /path/to/baritone-api-neoforge-1.11.2.jar`，并用 `--xvfb`、`--ffmpeg` 指向本机工具。运行器校验官方 JAR 的 SHA-256，仅在隔离客户端会话期间加载它。Fleck 地面路线由 Baritone 寻路，禁用挖掘、放置和冲刺。矿井入口使用勘测坐标，回船目标取实际舷梯落点附近。FFmpeg 需支持 `x11grab`、`libx264`。Nix 环境可加 `--client-prefix steam-run`。输出目录会保存实际执行的剧本、夹具、同一个隔离存档、双端日志和 `continuous.mp4`。两段剧本在起飞、进场、Fleck 地面与重登、返航推进及 Hearth 加工时启动帧时间采样。完整采样以客户端 `PROBE FRAMES` 行记录平均 FPS、P50/P99 帧时间和远景渲染 CPU/GPU 时间。录像帧率是录屏参数。

1. 复用 `acceptance.py` 的准备实例、客户端/服务端启动、双端 ACK 和命名检查。准备两份剧本，分别对应唯一一次重启前后。运行器在第一次干净退出后将本次 UUID 与交接回执传给第二段。保留前后两套日志，汇总到一个 `result.json`。先做不启动游戏的配置检查，再用短场景验证同一存档跨 JVM 的交接和录像连续性。
2. 在私有 Xvfb 上从第一次客户端启动前持续录到最终退出，使用 1280×800、60 fps、H.264、CRF 18。重启等待也留在同一原始 MP4。各检查点写时间戳以便回看，结束后用 FFprobe 核验文件和规格。
3. 每阶段设有限时的状态检查。固定坐标只用于已勘测的地形路点，进近、下降及登船交接按实际模式、船位和服务端状态触发。任一必需检查失败即停止探针输入。客户端仍在线时，保留双端和录像最多 10 分钟，并立即抓取客户端截图、原船舷梯状态和服务端回执。`handoff-<服务端>-<客户端>.json` 记录现场日志、私有显示和控制文件路径。将 `snapshot` 或 `quit` 写入临时文件并原子重命名到控制文件路径，可分别追加一次双端快照或结束客户端。接管结束后自动保存当前隔离存档并关停，失败仍计入验收结果。正式结果只接受从起点一次启动自然跑完的证据链。失败存档可用于后续诊断。
4. 分别给出流程通过和着陆质量。连续主线通过要求从起点到电路的所有检查点齐全、两端回执和关停保存通过，且全程同一世界和船。Fleck 强制离舵、绕梯下船，或 Hearth 接触时掉血，均须在结果首页列明对应着陆检查未通过。人工只需回看两处接地与舷梯、Fleck 最后一段登船和 HUD 提示。

## 实跑结果

- `build/acceptance/continuous-12/` 从预备码头存档出发，经实际舵组装 Copper Swift，转移分馏产物各 1,000 mB，并飞抵 Fleck。进近时服务端采样的船底投影距折点至少 374 格。干地低速接触持续 40 个客户端 tick，服务端接地快照中玩家为满血，舷梯 `length=0.0`、`settled=0`。剧本在等舷梯展开时超时，随后保存并关停。`result.json` 保留船体 UUID，`continuous.mp4` 经 FFprobe 验证为 H.264、1280×800、60 fps，时长 255.25 秒。
- `build/acceptance/continuous-restart-smoke/` 的两个真实客户端会话在同一隔离世界完成保存和重启回读。录像覆盖两次会话，时长 228.8 秒。完整路线仍待验证 Fleck 沿梯下船、采矿、带货重启重登原船，以及 Hearth 卸货和电路产出。
- 试跑使用预制船体和码头、已发放的精密机构、码头期定位命令、能力接口转油、供给的采矿平台和煤。返航剧本另提供封闭工位、熔炉、煤、灌注机、红石和电力。运行环境是固定模组版本的 Gradle 开发运行时。
