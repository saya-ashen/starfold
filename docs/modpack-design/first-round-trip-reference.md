# 首次采矿往返：目标、燃料与交付记录

[阶段4](../escape-velocity-player-guide_zh-CN.md) · [首船参考](first-ship-reference.md)

本指南交付阶段4的出发、装载、返航和卸货流程。实际完整往返仍待独立游戏验证；阶段3的近地短飞与这里的离线示例不构成外星航程实测。

## 目标选择与出发

当前体验星系可先比较母星 Hearth 的小行星型卫星 Fleck 与岩质星 Anvil：两类矿表均含锇，属于母恒星系内旅行，无须星际引擎。在 Atlas 查看本次世界的实际目标、距离与相对接近速度，再结合探矿结果选择。轨道位置随时间变化，不能把配置的轨道半径当作当前位置之间的直线距离，也不能按固定星球编号选矿点。

出发前完成母星短飞、制动、落地和再登船。带铁镐、Ultimine、食物、照明、维修工具、连接材料、备用船壳及货舱空位。铁镐用于锇矿；批量采矿时保留脚下支撑和撤离路线。留出停泊、下船、找回船只的空间。

在驾驶状态下使用 `/starfold mark add home` 保存基地标记，`/starfold mark list` 查看标记。自动起飞点按星球记录；返回母星时选择母星的基地或起飞点，避免把外星起飞点当作基地。标记导航需要驾驶会话；太空航段按 Atlas 和目标相对仪表导航。

## 原锇目标与启动材料

本地固定版本 Mekanism / Generators `10.7.19.85` 的配方核对支持以下启动方案：一台热力发电机、一台冶金灌注机、两块基础控制电路。

| 材料 | 合计 |
| --- | ---: |
| 锇锭 | 4 |
| 铁锭 | 7 |
| 铜锭 | 2 |
| 红石粉（含电路灌注） | 6 |
| 木板 | 2 |
| 圆石（制作三台作为材料消耗的熔炉） | 24 |

另需已有或单独制作的冶炼熔炉、冶炼燃料和发电运行燃料。三台材料熔炉会消耗在机器配方中。发电机的前方输出面可对接灌注机启用的能量输入面；这是静态能力核对，尚未实测摆放和持续供电。

4原锇按1:1冶炼可覆盖这套设备的锇材料下限。任务保留8原锇与8锇锭门槛，给后续设备留余量；交流发电机保留为可选的 Create 旋转供电路线，不阻塞热力启动方案。

若还计划启动液氢设备，建议采16原锇，先炼8锭、另留8原矿。该建议不提高任务门槛，也不代表完整制氢工厂的全部物料已经备齐。分离器核心需要锇粉；当前富集仓为3原锇→4锇粉，把已冶炼的锭重新变成粉则需要粉碎机。不要为了当前8锭任务把所有后备原矿都炼掉。详细静态配方证据保存在 `build/stage4/recipe-audit.md`。

## 逐段燃料预算

柴油、汽油的当前燃料定义均为每 mB 冲量940、每1000mB质量47。储备油仍有质量；途中装入的受支持物理载荷增加返程负担。空桶数量、原矿物品数量不能直接换算成 Sable 质量，使用实际物理质量读数。B6-F 的空船静态质量323.5只适用于参考布局，装配器、改装及其他设备都要另外计入。

按母星起飞、去程加速、目标制动与落地、外星起飞、返程加速、母星制动与落地的顺序预算。每段使用前一段剩余的燃料；装矿后重新核对返程起飞时的湿重和升力。阶段3的123mB仅是一次短程近地样本，不能用于估算跨星球往返。

新增工具接受人工准备的 JSON：

```sh
python3 tools/ship/round_trip_budget.py --plan my-trip-plan.json
```

计划必填 `fuel`、`dry_mass`、`initial_fuel_mb`、`reserve_mb`、`legs`。每段必填唯一的 `name` 和非负 `delta_v`；可在装载后的第一段给出 `added_mass`，此质量会持续保留。可同时给出 `effective_gravity` 与 `lift_nozzles` 检查该段出发时的静态推重比。

例如下面只是**人为数字演示**，没有目标、航线或续航资格含义：

```json
{
  "fuel": "diesel",
  "dry_mass": 323.5,
  "initial_fuel_mb": 4000,
  "reserve_mb": 1000,
  "legs": [
    {"name": "outbound-example", "delta_v": 1},
    {"name": "return-example", "delta_v": 1, "added_mass": 10}
  ]
}
```

工具读取仓库当前燃料与推力定义，依次使用变质量火箭方程扣除燃料，保留不可支用的储备。理想模型没有自动计算重力损失、阻力、操纵、制动和落地；这些需求必须由输入者纳入各段推进预算。没有提供有效重力及喷口数量就没有检查升力。即使模型结果可行，也未证明实际航线可行或操纵可控。

## 采矿、装船与卸货

基础交付目标为至少8份外星原锇。首次落地后先记录着陆点和船只位置，安全停稳再离船。采矿后把原矿装入这艘船的货舱，记录准确数量、各油罐液位、船体身份及返程质量。**登记基地卸货前保留原矿**，不要用途中冶炼或原有库存替代运输核对。

母星落地后，对照出发、装矿、抵达时的同一船体身份，把原矿卸入基地仓库，再进行冶炼。八份是当前任务的基础门槛，后续大规模机器、船体和燃料工业需要继续采集。

任务链包含三项明确的手动记录：出发登记、装矿与返程复核、同船卸矿核对。现有外星着陆、返航进度记录玩家经历，物品任务检查持有；二者都不自动证明原矿来源或同船运输。

离线记录示例：

```sh
python3 tools/ship/voyage_log.py \
  --log docs/examples/first-round-trip-log.json
```

随附文件完全是合成示例。建立真实记录时替换玩家UUID、船体UUID、目标编号、世界 tick、油量与货物读数；船体UUID应取实际地图数据或只读诊断回执，不能以船名代替。顺序为 `home_departure`、`offworld_landing`、`ore_loaded`、`offworld_departure`、`home_landing`、`unloaded`。保留对应截图或回执。

检查器拒绝身份变更、时间倒序、初始携带目标矿物、货物中途改变及卸货数量不符。当前单条记录不支持补油，油量增加会要求拆分记录；有补油的真实航次应另留补油证据，不修改原始读数来迁就工具。`consistent: true`只表示填写的数据一致，不认证游戏行为、矿物产地或阶段4完成。

## 找船与应急

- **离船或迷路：** 先使用 Atlas 的船只记录和外星着陆标记找船，回到已停稳的船，再展开登船梯。出发前就在基地演练这条路线。
- **返程油量不足：** 保持安全停泊，停止不必要的悬停与推进，安排送油或救援船。不能假定目标星存在可用油田或随身就能建起炼油链。
- **满载起飞不了：** 重算实际湿重与有效重力，卸下非必要载荷或安排运输；不要依赖起飞后才烧掉超重燃料。
- **保存退出：** 留下停泊位置、船只身份、燃料和货物读数。重进后先核对状态，再开始下一航段。
- **死亡与掉落：** 原有死亡和掉落规则继续适用；备用交通、留在基地的燃料与救援准备需要事先安排。新增教程没有恢复物资、墓碑或重生传送机制。
