# 路线图

[English](ROADMAP.md)

当前版本之后计划做什么，以及每一项想到了什么程度。这里没有承诺，也没有日期。标为*已定*的条目有商定的方向；
*设想*表示讨论过、在纸面上判断可行；*未知*指出动手之前必须先回答的问题。

## 0.2.0 已完成

- **代码更容易上手。** 按子系统分包、统一排版、依赖只朝一个方向：geometry、chart、planet、sky、worldgen、universe、
  ground、flight、ship、space，然后是 waypoint、render 和 dev，接线在最上面。下层要用到上层时，只通过接线安装的
  host 接口。剩下朝上的引用只有几处指向 mixin，以及一处从 sky 指向 universe。
- **天体模型的第一部分。** 太阳、行星和卫星是同一种天体：运动（固定，或绕另一个天体的轨道）、半径、是否发光，以及
  决定引力、交接和船体重量的作用范围。固定的一对母星已经取消，一个星系可以只有一颗行星，一个世界的所有天体都在
  同一个维度里。
- **卫星**，由数据包定义，有完整地表；在地面上能看到天空中的其他天体。
- **太空中无人驾驶的飞船**会滑行减速，然后相对最近的天体停在原处，保存重进后也一样。

## 下一步：完成天体模型 *（已定）*

计划是一个由部件组成的天体类型：

| 部件 | 内容 | 是否必有 | 状态 |
|---|---|---|---|
| 身份 | 区域及其中的序号、名字、种类 | 必有 | 未做：天体仍是全宇宙统一的一个编号 |
| 运动 | 固定、绕另一个天体的轨道，或由物理驱动 | 必有，三选一 | 固定和轨道已完成；物理驱动未做 |
| 范围 | 半径、引力的强度和作用范围、飞船被交接的高度 | 必有 | 已完成 |
| 外观 | 从远处怎么画 | 必有 | 未做 |
| 地表 | 真实区块：存储、形状、生成 | 可选 | 已完成 |
| 行为 | 发光、危险区、卫星的功能 | 可选 | 发光已完成 |

各种天体是部件的组合：太阳固定并发光；星球绕太阳、有地表；天然卫星绕星球；气态星球没有地表；飞船由物理驱动，
方块在船体里。飞船目前还不是天体，仍是单独的记录。

- 天体的身份是区域加上其中的序号，而不是全宇宙统一的一个编号，这样以后可以把区域分开。

## 建立在天体模型之上

- **空间站：只有一个面的天体。** 空间站是只有一个平面、没有地形的天体。它有自己的区块，像星球一样到达和着陆，
  有没有船在附近都存在。它绕一颗行星运行，始终以同一面朝向行星；站上的重力指向这颗行星，所以行星在脚下，飞船从
  背向行星的一侧降落。除此之外它不能移动。它没有接缝，也没有折点：就是一座普通的人造建筑。走出边缘会朝行星
  落下。空间站可以写在数据包里，也可以由玩家在游戏中新建，先做数据包。*（已定）* 以后可以做失重的空间站：让这个
  天体没有引力，并给站上的人另一种移动方式。*（设想）* 待定：一个面最小能多小，有镂空的结构从远处怎么画。
- **人造卫星：一条轨道记录。** 以方块的形式建造并运上去，释放时变成存档记录，回收时变回物品；在算出的位置画一个
  小模型。第一版只做结构：发射、在轨、回收，以及夜空里的一个亮点。*（已定）* 卫星的用途以后再加；提到过导航、
  测绘和中继。*（设想）*
- **留在原地的飞船。** 附近没有人的飞船变成一条有身份和位置的记录，这样可以离开后再找回来，多艘船也可以同时
  各在一处。这也解除了现在太空区域只能有一艘领头船的限制。*（设想）* 已经做了一部分，放在开发开关后面，发行版中
  关闭：太空中的船体卸载时记下相对所属天体的位置，之后在那里重新加载。发布测试中在当前位置唤醒失败，所以在查清
  原因之前保持关闭。
- **有作用范围的引力。** 每个天体在一定距离内有引力，超出则为零；只计算最近的一个天体。*（已定）* 作用范围已经是
  天体的属性，决定交接高度和船体重量；无人驾驶的船相对最近的天体保持不动。剩下的是太空区域本身的引力，以及靠试飞
  重新调到达和悬停的手感。

## 远期：大型多人 *（设想，现在不为它做任何实现）*

原版服务器在一个线程上依次运行所有维度，所以把区域做成维度并不能用上更多的核；而在同一个进程里给每个区域一个
线程，与 Create 和 Sable 一起使用时无法保证安全。如果大型服务器成为目标，可行的形式是多个进程：

- 每个区域（例如一个恒星系）是一个普通的服务器进程。跃迁把玩家和他们的船转到另一个进程，玩家直接连接过去。
- 一个轻量的协调进程负责登记（哪个进程运行哪个区域、每个玩家和每艘船在哪里）、执行交接，并保存各区域共用的
  内容：统一的时间，以及跨区域可见的记录，如留下的飞船、空间站和卫星。它自己不运行世界。
- 交接绝不能丢失飞船，也不能出现两艘：交接先被持久记录，双方都确认后才算完成。
- 协调进程停止时，各区域继续运行，只是不能跃迁。
- 单人和小型服务器仍是一个进程。交接一艘船是一个明确的操作，在那里直接执行，在集群上经由协调进程执行。

*未知：* Sable 船体能否连同方块、实体和乘员完整保存，并在另一个进程里恢复。留在原地的飞船需要同样的能力，所以
这个问题会在做天体模型时得到回答。天体模型会保持这件事所依赖的三个性质：身份由区域和序号构成、飞船可以存成
记录、位置只由时间决定。

"把区域做成维度、在同一个进程里用跃迁连接"也考虑过，已搁置：服务器的开销与现在的单一世界大致相同。
